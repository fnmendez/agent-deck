# Strict one-shot terminal send

`agent-deck session send FULL_SESSION_ID --strict-once --expected-thread NATIVE_THREAD_UUID --json --message-file -` reads the exact prompt from stdin. No prompt file is needed. This release supports the literal `claude` and `codex` tool types on macOS (Darwin), plus local AgentDeck `claude` sessions on Linux/amd64. Linux Codex and every other platform/tool combination return `refused`, `attempted: false`, `reason: "unsupported_platform"`. Other send modes are unchanged. Strict mode cannot be combined with `--no-wait`, `--defer-if-busy`, `--draft`, `--wait`, or `--stream`.

Strict mode refuses before terminal input unless the target has a matching idle authority (a hook, or the exact hookless Linux-native status proof below), a matching native thread anchor, an empty recognized composer with its visible cursor at the input position, raw terminal mode and bracketed paste enabled. A non-control-mode attached client active within the last 60 seconds, unknown client activity, copy mode, hidden cursor, vim mode, busy indicators, approval menus, unknown footers/placeholders, drafts and capture failures refuse. Claude requires its exact owned no-follow `sessions/<pane-pid>.json` record with matching PID/sessionId, process start, platform PID domain, tmux identity and cwd. Darwin native `ps` reads retain `TZ=UTC`, `LC_ALL=C`. Linux accepts only amd64, the canonical `$HOME/.claude` record schema and the stable native package rooted at `$HOME/.nvm/versions/node/v24.18.0/lib/node_modules/@anthropic-ai/claude-code`. It binds the exact full AgentDeck instance, its persisted nondefault tmux socket/session, pane/session/window IDs, PID/PPID/PGID/SID/TPGID/TTY, UID, cwd, the exact root-owned no-follow `/etc/machine-id`, PID namespace, kernel start ticks and the package's `bin/claude.exe`. The native `pidDomain` must be exactly `linux:<32-lowercase-hex-machine-id>:pid:[<namespace-inode>]`; the dashed kernel boot ID is not this domain value. PPID and SID are observed process facts only; they do not claim that the Claude process is a direct child of the tmux server. It uses bounded `/proc` and machine-ID/record reads and never reads `/proc/*/environ`. A missing, unknown, duplicate or malformed native record refuses. Codex requires the uncached tmux `CODEX_SESSION_ID` anchor plus an open CLI root rollout in the current descendant Codex process. Codex reads only the bounded first `session_meta` record, requires `source: "cli"` and `id == session_id == expected_thread`, and allows separate subagent rollouts without mistaking them for the main thread. Codex must be a running foreground TUI in the pane TTY/process group with the current native cwd matching the project; a background or suspended descendant cannot authorize a send. The unique main rollout must have a writable numeric FD with matching device and inode. Each pathname component is opened relative to a held nonsymlink directory; directory identities, root FD/access/device/inode, process ancestry and start times are reread and must remain stable within and across proof calls. The verified root/executable descriptors are held during revalidation. Missing or changed native process/descriptor evidence refuses. No account, model, session or runtime is changed.

Claude's exact `Stop` hook is durable for a continuously verified versioned-native process. After the normal two-minute fast path expires, strict mode accepts only `tool=claude`, `status=waiting`, literal `event=Stop`, the exact thread and cwd, an accepted hook generation/sequence, and a hook timestamp at or after the actual process start. Darwin parses that start as UTC from the same whitespace-folded `ps lstart` value matched to the native record. Linux derives it from the boot time plus the kernel start ticks, cross-checks the record's millisecond `startedAt`, and rereads the full proof at the end. Future and pre-process timestamps refuse. Fresh hook behavior is unchanged and does not require an event or cwd.

If and only if the hook read returns `hook_unavailable`, Linux/amd64 Claude may use the exact strong native record as a separate idle authority. Both full native proofs must report an internally stable literal `status: "idle"`, the exact `statusUpdatedAt`, and the same status/status-timestamp/start tuple across passes. The unrelated general `updatedAt` field remains type/bounds checked but is not idle authority. The millisecond status time must be at or after both the native `startedAt` and kernel-derived process start, and no more than five seconds in the future. Each pass is paired with an independent full read-only tmux/client/raw-mode/composer observation; any draft, modal, busy native status, missing/invalid/future/changing status timestamp, pane/identity change or authority-source change refuses before terminal effect. A present but invalid hook is never bypassed. Darwin, Codex, other architectures and weak/legacy Claude identity still require hooks.

Durable admission additionally binds the exact executable, foreground PID/PGID/SID/TPGID/TTY, owned no-follow native PID record, and the one transcript root derived directly from that record's cwd/sessionId. Record/root path, ancestors, device, inode, mode, link count, size and modification identity are reobserved; record contents are bounded and hash-bound. Linux opens and holds no-follow descriptors for the stable package directory, its bounded `package.json`, and `bin/claude.exe`; the package name/version must be `@anthropic-ai/claude-code` and exactly the native record version. Package and executable path, ownership, mode, link count, content and inode must remain stable. Normally `/proc/<pid>/exe` must resolve to and match that held stable executable descriptor. One fail-closed atomic-update residue is also recognized: `<same Node v24.18.0 @anthropic-ai parent>/.claude-code-<exactly 8 ASCII alphanumerics>/bin/claude.exe (deleted)`. Its held proc descriptor must be an unlinked regular file (`nlink=0`) on the stable executable's device, with a different nonzero inode but the exact stable owner, mode and size; a bounded SHA-256 read of the held descriptor must equal the concurrently held stable package executable hash. Record and package versions must still match exactly. Other deleted/temp paths, linked impostors, symlinks outside the closed tree, other Node versions and any hash/version/metadata change refuse. There is no project scan, glob fallback, prefix UUID, newest-root selection, cached status or registry-only fallback. Both verifier callbacks compute the full proof even when the first hook is still fresh. Stable signatures exclude only the transient runnable/sleeping process state and the record's mutable name/status/update timestamps; those values remain type/bounds checked on every observation, and stopped/zombie/dead states still refuse immediately. Consequently a native Claude send requires the hardened record, package and root even during the fresh window; a missing root, unsafe record mode/hardlink or authority churn refuses safely. Their signatures must match, so a fresh-to-stale boundary is safe and a strong-to-legacy downgrade refuses. Darwin's literal `claude`/`claude-*` process-name compatibility remains fresh-only.

Linux process state is an explicit allowlist: only `R`, `S`, `D` and `I` are live. Job-control stop `T`, tracing stop `t`, zombie `Z`, dead `X`/`x` and every unknown state refuse. The read-only probe remains Claude-only on Darwin; a Codex row is rejected at the command gate before any tmux snapshot.

`agent-deck -p <profile> session strict-probe FULL_SESSION_ID --json` performs two independent full read-only tmux/client/raw-mode/empty-composer observations, each followed by the stateful native/idle verifier, without a message. It opens only an existing current-schema registry through a stable private DB/WAL/SHM snapshot under `TMPDIR`, so the newest committed WAL row is visible while the live registry remains byte-identical; it rejects a rollback journal and bounds the complete source triplet to 512 MiB before its three reads plus one private copy. It never initializes, migrates, checkpoints, saves or updates source timestamps, and closes/removes the snapshot immediately after resolving the exact instance, before runtime proof begins. It accepts only an exact live local Claude ID and has no path to `StrictSendOnce`, buffer staging, paste, keys, draft clearing or submission. Its closed JSON reports the thread, durable Stop decision, hook ages, UTC process start and hashes of both proof signatures; hookless admission keeps `durable_stop: false`, an unavailable start is the empty string, and it never emits paths, pane text or transcript content. A composer-guard refusal reports its closed composer reason (for example `busy_or_modal` or `claude_empty_hint_unverified`), the same identifier a strict send would refuse with; metadata, client, raw-mode and capture failures, and any untyped or unsafe error, still report `tmux_observation_unavailable`. A successful probe certifies only those two completed native/idle/tmux/composer observations. It does not certify the later 500 ms send-frame budget, a terminal effect or application consumption.

Codex geometry is deliberately restricted to the measured **141 columns × 67 rows**, cursor `(2,64)` in zero-based coordinates, blank padding rows63/65 and the complete main footer at row66. The sender retains dimensions from both metadata samples and requires a full67-row capture; missing, cropped, shifted, resized or otherwise unsupported frames refuse. It never resizes a pane. This is a measured contract, not a claim that any screen above an arbitrary size is safe. Claude geometry was not broadened by this correction.

The pinned renderer explains why geometry is load-bearing. [ChatWidget](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/chatwidget/rendering.rs#L69) reserves BottomPane as non-flex with one top inset; [BottomPane](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/bottom_pane/mod.rs#L1953) reserves Composer as non-flex before other panels. [Flex allocation](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/render/renderable.rs#L302) gives non-flex children their requested space first. [Composer desired height](https://github.com/openai/codex/blob/rust-v0.153.4/codex-rs/tui/src/bottom_pane/chat_composer.rs#L4640) includes remote-image rows and their separator, not just text. For the supported normal-main layout with a one-row footer, nonempty images request their rows plus separator, textarea and padding; at the recorded67-row screen this gives visible image rows, or eliminates the textarea when images saturate its space. By contrast, a three-row composer rectangle leaves one textarea row, making `min(image_count, textarea_height-1)` zero: the four-row compact example can hide images behind the same styled placeholder. It is refused before staging. The source-derived fixture exercises the production capture/admission boundary with zero staging and zero submit.

The saved real fixture remains a **lower-region recording**, not a whole-pane or idle certificate. Tests reconstruct its measured global coordinates using synthetic blank history; actual private history was not captured into the fixture. Full capture, geometry, native idle, client and other guards remain required in production.

The transport pins session ID, pane ID and pane PID, brackets each capture with metadata reads, rechecks native thread and idle status, then rechecks the active pane and composer immediately before one framed paste and one Enter in the same tmux command list. Metadata includes `#{version}` and must be byte-stable around each capture and identity-stable across both captures. Tmux 3.7b continues to require the known `bracket_paste_flag=1`. Tmux 3.6 does not expose that format, so an empty flag is only a compatibility candidate when the observed server version is exactly `3.6`; a known false flag still refuses. That candidate is admitted only after the full durable Linux/amd64 Claude native proof above. The sender then stages exactly one internally generated `ESC[200~`/`ESC[201~` pair around the already control-free message and uses raw `paste-buffer` without `-p`, preventing tmux from omitting or duplicating the frame. Wrong/changed versions, Darwin, non-Claude tools, Linux Codex and weak native proof refuse before terminal input. This is not a generic unknown-is-true rule.

The transport refuses if the final snapshot is older than 500 ms at tmux invocation. This bounds observation age at invocation, not OS scheduling or tmux processing latency. It never presses Ctrl+C, Escape, clears/restores a draft, retries Enter or resends. Input must be valid UTF-8, nonempty and at most 64 KiB, with no control characters other than LF. Carriage returns are refused rather than normalized.

JSON fields are at the root:

- `delivery: "refused", attempted: false`: no terminal send was invoked. The queue may hold and retry after the refusal reason changes.
- `delivery: "unknown", attempted: true`: a terminal attempt was invoked. Never replay automatically. This remains unknown even with exit 0 and `success: true`; those only report that tmux accepted the command list. A transport error exits 1 with the same unknown outcome.
- `reason`, `session_id`, `expected_thread` identify the outcome and intended binding without echoing prompt or pane content.

The private tmux buffer is staged in server memory and cleaned up on all normal returns. Process termination may leave an unused named buffer; that is not delivery evidence. A caller crash, timeout or missing/malformed response must be treated as unknown, never as a safe refusal.

This is **not an atomic application enqueue**. The application can transition to a modal, start work, change threads or receive operator input after the final observation. tmux metadata/native anchors and hooks can lag; they are evidence, not a consumption acknowledgement. An async TUI may swallow the one Enter immediately following paste. If an operator starts typing after the final observation, the paste can still collide with their draft. These residual terminal races remain unknown and do not authorize rescue keys. Confirm consumption only from independently correlated native conversation events. No live send or runtime activation is covered by synthetic tests; the director owns that verification.
